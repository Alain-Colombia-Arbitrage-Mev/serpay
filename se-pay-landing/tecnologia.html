Tecnología · smart contracts · código abierto

Reglas escritas en código.
Que nadie puede cambiar a escondidas.

En un banco tradicional, las reglas viven en un contrato de papel y en sistemas que no ves. En SE pay viven en smart contracts públicos: cualquiera puede leerlos, auditarlos y comprobar que se cumplen.

Blockchain, sin tecnicismos

Cuatro piezas. Eso es todo.

01 · Wallet

Tu cuenta, tu llave

Tus tokens y tu saldo en USDC viven en una wallet a tu nombre. SE pay no puede moverlos sin las reglas del contrato.

02 · Smart contract

Un programa que cumple

Código publicado en la blockchain que ejecuta las reglas: cobra comisiones pactadas, bloquea fondos, reparte ganancias.

03 · Token

Tu participación

Cada token representa una fracción de los derechos económicos de un proyecto. Se registra a tu nombre y se puede transferir.

04 · Libro público

Todo queda registrado

Formato de contrato · ERC-6960

Un estándar pensado para activos reales.

ERC-6960, o Dual Layer Token, organiza los tokens en dos capas: una principal y una secundaria. Es ideal para tokenizar activos reales que se dividen en series, tramos o lotes.

CapaEn SE payEjemplo
mainIdEl proyecto1 = Atacama II
subIdLa serie de la ronda1 = Serie A
amountTu participación9.850 tokens = US$9.850
  • Un solo contrato para todo el catálogo: más simple de auditar.
  • Cada serie puede tener sus propias condiciones sin crear un token nuevo.
  • Transferencias y permisos por proyecto y por serie.

interface IDLT {
  event Transfer(address indexed sender, address indexed recipient,

    uint256 mainId, uint256 subId, uint256 amount,

  function approve(address spender, uint256 mainId,
    uint256 subId, uint256 amount) external returns (bool);

  function subBalanceOf(address account, uint256 mainId,
    uint256 subId) external view returns (uint256);
}
RaiseVault.sol · ejemplo simplificado
function invest(uint256 mainId, uint256 subId, uint256 amount) external {
  Raise storage r = raises[mainId][subId];
  require(block.timestamp < r.deadline, "Ronda cerrada");
  uint256 fee = amount * DEPOSIT_FEE_BPS / 10_000; // 1,5 %
  uint256 net = amount - fee;
  require(r.raised + net <= r.hardCap, "Hard cap alcanzado");

  usdc.transferFrom(msg.sender, address(this), amount);
  paid[mainId][subId][msg.sender] += amount; // incluye el fee
  r.raised += net;
  token.mint(msg.sender, mainId, subId, net);
}

function markLive(uint256 mainId, uint256 subId) external onlyOperatorAndOracle {
  Raise storage r = raises[mainId][subId];
  require(r.closed, "Ronda abierta");
  r.liveAt = block.timestamp;           // desde aquí puede haber distribuciones
  emit WentLive(mainId, subId, block.timestamp, r.goLiveBy);
}

function isDelayed(uint256 mainId, uint256 subId) public view returns (bool) {
  Raise storage r = raises[mainId][subId];
  return r.liveAt == 0 && block.timestamp > r.goLiveBy + 90 days;
}

function refund(uint256 mainId, uint256 subId) external {
  Raise storage r = raises[mainId][subId];
  require(block.timestamp >= r.deadline && r.raised < r.softCap, "Sin reembolso");
  uint256 back = paid[mainId][subId][msg.sender];
  paid[mainId][subId][msg.sender] = 0;
  token.burn(msg.sender, mainId, subId, token.subBalanceOf(msg.sender, mainId, subId));
  usdc.transfer(msg.sender, back); // 100 %, fee incluido
}

Código ilustrativo y simplificado. La versión en producción incluye controles de acceso, pausas de emergencia y protección contra reentrada.

Comisiones al instante

Se confirma un pago.
Cinco wallets cobran en el mismo segundo.

Las comisiones de Vox Populi no esperan a fin de mes. Un contrato las reparte en la misma transacción en que se confirma cada suscripción o acción verificada, y SE pay cobra su parte primero.

Pagos dentro de la appSi la suscripción se paga en USDC o con tarjeta en SE pay, el dinero entra al contrato y se reparte en el mismo bloque: 65 % a SE pay y el resto a los niveles desbloqueados.
Pagos por el App StoreApple avisa cada compra o renovación al servidor de SE pay al momento (App Store Server Notifications). Un oráculo firma el evento y el contrato paga desde CommissionReserve, una reserva que solo se llena con ingresos ya cobrados.
Cómo se llena la reservaSale de la parte de SE pay, nunca de la red ni de los participantes: el 15 % del 65 % de SE pay (≈9,75 % del ingreso neto) va a CommissionReserve hasta que cubre 1,5 veces lo que la red cobra antes de que pague la tienda. Al llegar a esa meta, el aporte se detiene solo, y se reactiva si la reserva baja.
Si la reserva no alcanzaEl pago queda en cola y se ejecuta en cuanto entra el siguiente ingreso. El contrato nunca paga más de lo que hay: SE pay no se endeuda con la red.
A tu wallet o a tu bancoPor defecto la comisión llega en USDC a tu wallet en segundos. Si eliges cobro bancario, se convierte y se envía automáticamente a tu cuenta local en menos de 5 minutos por transferencia instantánea, con el fee de retiro de 1,5 %.
ReembolsosSi una suscripción se reembolsa, el contrato descuenta esa comisión de los siguientes pagos de cada nivel.
CommissionSplitter.sol · ejemplo simplificado
uint16[5] LEVEL_BPS = [1800, 700, 500, 300, 200]; // 35 %

function payout(address subscriber, uint256 netAmount) external onlyTrusted {
  // 1. SE pay primero: 65 %. Si la reserva está bajo su meta,
  //    el 15 % de esa parte la recarga automáticamente
  uint256 sePay = netAmount * 6500 / 10_000;
  uint256 topUp = reserve.belowTarget() ? sePay * 1500 / 10_000 : 0;
  usdc.transfer(address(reserve), topUp);
  usdc.transfer(treasury, sePay - topUp);

  // 2. Sube por el árbol de referidos, hasta 5 niveles
  address up = referrerOf[subscriber];
  for (uint256 i; i < 5 && up != address(0); i++) {
    uint256 fee = netAmount * LEVEL_BPS[i] / 10_000;
    if (rankOf(up) > i) {            // nivel desbloqueado
      fee = _settleDebt(up, fee);        // descuenta reembolsos
      usdc.transfer(up, fee);            // pago inmediato
      emit Commission(up, subscriber, i + 1, fee);
    } else {
      usdc.transfer(treasury, fee);      // sin arrastre
    }
    up = referrerOf[up];
  }
}
Ciclo de vida de una ronda

Del primer aporte a la última distribución.

1Publicación

Se despliega la serie con soft cap, hard cap, fecha límite y fecha comprometida para estar al aire.

2Ronda abierta

Los aportes quedan en garantía en RaiseVault.

3Soft cap

Si no se alcanza: reembolso del 100 %. Si se alcanza: sigue.

4Cierre

Por hard cap o por fecha. No se aceptan más aportes.

5Desembolso

Por tramos ligados a hitos verificados, con comisión de desembolso.

6Al aire

Tras el tiempo de espera fijado en el contrato. Si se retrasa más de 90 días, queda marcado en público.

7Operación

Ingresos y gastos registrados on-chain, auditados cada trimestre.

8Distribuciones

Waterfall reparte en USDC a las wallets de los tenedores.
